# 排名口径

本文件是排名逻辑的唯一事实来源。`scripts/fetch_rank.py` 照此实现，改口径先改本文件。

## 原则

只使用各平台**原生公开的真实计数**。不构造代理指标、不估算、不编造。

「点击率」在四个信源中全部不公开（dev.to 的 `page_views_count` 仅文章作者可见），因此该维度**不参与排名**，也不在产物中出现。

## 指标与权重

基础权重按用户给定的优先级「评价量 → 转发量 → …」：

| 指标 | 基础权重 | HN | Reddit | HF | dev.to |
|---|---|---|---|---|---|
| 评论量 `comments` | 0.5 | `num_comments` | `num_comments` | `numComments` | `comments_count` |
| 转发量 `shares`   | 0.3 | 不公开 | `num_crossposts` | 不公开 | 不公开 |
| 点赞/票数 `votes` | 0.2 | `points` | `ups` | `paper.upvotes` | `public_reactions_count` |

**缺失指标的权重按比例重分配**给该信源可得的指标。例如 HN 无转发量：

```
comments = 0.5 / (0.5 + 0.2) = 0.714
votes    = 0.2 / (0.5 + 0.2) = 0.286
```

## 归一化：分位排名（rank-percentile）

在**同信源 + 同时间窗口**的候选池内，把每个指标转成 0~1 的分位值（并列取平均秩）：

```
percentile(x) = (该值的平均秩 - 1) / (池大小 - 1)
```

池大小为 1 时该指标记 1.0。

**为什么不用 min-max**：互动数据是重尾分布。实测 HN 七天榜首 1978 分，而池中第 281 名才刚过 100 分 —— min-max 会让单个爆款把整张榜压成一条贴近 0 的平线，中段条目彼此再也分不开。分位排名对长尾稳健。

## 综合得分

```
score = Σ (重分配后的权重_m × 分位值_m)
```

得分只在**同信源同窗口内**有比较意义。跨信源不比大小 —— 见下面的名额制。

## 候选池定义

| 信源 | 池 |
|---|---|
| HN | 窗口内 `points > 20` 的 story（实测 7 天约 680 条，单次请求即可取全，无需翻页） |
| Reddit | `r/LocalLLaMA` 的 `top?t=week` 前 100 条，再按 `created_utc` 过滤到目标窗口 |
| HF | 近 7 天逐日 `daily_papers` ∪ `papers/trending` 中落在窗口内的条目，按论文 id 去重 |
| dev.to | `?top=7` / `?top=3` 各取 100 条 |

**HN 的 `points > 20` 阈值**：低于此线的帖子进不了任何榜单，纳入只会稀释分位分布。阈值可用 `--hn-min-points` 调整。

**HF 必须逐日补齐**：`papers/trending` 是历史热门榜而非最新榜 —— 实测 50 条中仅 8 条落在 7 天内、**0 条落在 3 天内**。另注意 daily_papers 周末不发布，逐日拉取会遇到空日，属正常。

## 名额分配

| 版块 | HN | Reddit | HF | dev.to | 合计 |
|---|---|---|---|---|---|
| 七日要闻 | 4 | 3 | 2 | 1 | 10 |
| 三日速览 | 2 | 1 | 1 | 1 | 5 |
| Hacker News 专栏（3 天） | 5 | — | — | — | 5 |

**用名额而非全局总榜**，因为 HN 的 `points` 与 dev.to 的 `reactions` 不是一个量纲，任何跨平台的分数相减都是伪精度。名额制让四个信源都保证露出，也让优先级顺序真正生效。

**顺位补位**：某信源候选不足或采集失败时，空缺名额按优先级顺序（HN → Reddit → HF → dev.to）交给下一家，并在产物中显式标注该信源的状态，不静默留白。

## 去重

1. **跨信源**：按归一化后的目标 URL（去 scheme / `www.` / 末尾斜杠 / `utm_*` 等跟踪参数）与规范化标题比对。同一篇论文常同时出现在 HN 与 HF —— 保留优先级高的信源，并在其条目上标注「另见 X」。
2. **跨版块**：三日速览排除已进入七日要闻的条目，HN 专栏排除前两个版块已用的条目。默认开启，保证一期 20 条互不重复；`--allow-cross-section-dupes` 可关闭。

## 时间字段

| 信源 | 用于窗口过滤的时间 |
|---|---|
| HN | `created_at_i`（Unix 秒） |
| Reddit | `created_utc` |
| HF | `paper.submittedOnDailyAt` → 外层 `publishedAt` → `paper.publishedAt`（依次回退）。用上榜时间而非论文发表日，更贴合「最新消息」语义 |
| dev.to | `published_at` |

窗口边界在运行时按 UTC 计算：7 天 = `now - 7×86400`，3 天 = `now - 3×86400`。

## 版块内的展示顺序

先按**信源优先级**（HN → Reddit → HF → dev.to），再按**组内得分**降序。

不按 score 做跨信源全局排序 —— 不同平台的分位值来自不同的候选池，彼此不可比，那样排出来是伪精度。这个顺序同时让用户给定的信源优先级在版面上真正可见。
