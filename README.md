# TrendBrief · 技术热帖简报

一条自然语言指令，换回一份带 200 字中文摘要、报纸风格排版的技术资讯页面。

**在线访问**：https://subtle-clafoutis-df6797.netlify.app/

| 页面 | 内容 |
|---|---|
| [`index.html`]| 🐮 **The Daily Bull** 新闻板 —— HN 与 HF Papers 近 7 天榜单切成等量批次，可往下翻、可星标收藏 |
| [`digest.html`] | 📰 **The Daily Digest** 日报 —— 四信源固定 20 条，按时间窗口分版块，可按信源筛选 |

## 解决什么痛点

想跟进技术圈动态，就得挨个刷 Hacker News、r/LocalLLaMA、Hugging Face Papers、dev.to，四个站点四套热度口径，热帖混着噪音，读完还得自己翻译消化。本项目把这套动作压成一句话：抓取、去重、统一口径排名、写中文摘要、排版成页，全部自动完成。

## 快速开始

在 Claude Code 里直接说人话即可，无需手敲命令：

```
帮我出一份今天的技术新闻简报        → 日报
每天的 HN Top30 和 HF Top10        → 新闻板
```

以下说法都会触发（skill 的 `description` 已登记这些语义）：「技术新闻简报」「AI 资讯汇总」「最新热帖」「今天有什么值得看的」「爬这几个网站给我最新消息」，或直接点名「用 tech-news-digest 出一期」。

**可选的附加指令**，写在同一句话里即可：

| 你想要的 | 这么说 |
|---|---|
| 放宽 / 收紧 HN 门槛 | 「HN 门槛降到 10 分」 |
| 跳过正文抓取快速验证 | 「只跑排名，不抓正文」 |
| 传入浏览器导出的 Reddit 数据 | 「Reddit 数据用我这份 `top.json`」 |
| 补写新闻板某一批的摘要 | 「把第 3 批的摘要补上」 |
| 改排名权重或名额 | 「转发量权重提到 0.4」（会先改 `references/ranking.md` 再改脚本） |

## 两种产出的分工

|  | 日报 `digest.html` | 新闻板 `index.html` |
|---|---|---|
| 信源 | HN · r/LocalLLaMA · HF Papers · dev.to | HN · HF Papers |
| 条数 | 固定 20 条（7 天 10 + 3 天 5 + HN 专栏 5） | 每批 40 条（HN 30 + HF 10），可翻多批 |
| 组织方式 | 按时间窗口分版块，跨信源固定名额 | 同一榜单往下翻，排名全局连续 |
| 交互 | 顶部频道 Tab 按信源筛选 | 更新按钮翻批次、星标收藏、收藏夹视图 |
| 摘要 | 20 条全写 | 前 2 批 80 条，其余标「摘要待补」 |

新闻板的批次数受 HF 限制 —— HF 日报每天仅 23–33 篇，7 天约 136 篇可切 13 批；HN 同期 651 条本可切 22 批。

## 核心设计

- **可解释的排名口径**：评论量 0.5 › 转发量 0.3 › 点赞量 0.2，同信源内做分位归一，缺失指标按比例重分配权重。只用平台原生真实计数，**不构造代理指标** —— 「点击率」四个平台全不公开，因此不参与排名。用分位而非极值归一，是因为互动数据呈重尾分布。
- **名额制而非全局总榜**：得分只在同信源内可比，拿 HN 的 `points` 去减 dev.to 的 `reactions` 是伪精度。日报因此给各信源固定名额；新闻板则不做分配，各池内按分数直接切段。
- **缺额轮转补位**：某信源采集失败时，空缺按 HN → Reddit → HF → dev.to **轮流各补一席**，而非让最高优先级的一家吃满。此前 Reddit 缺席时 HN 一度占到 20 条里的 15 条 —— 优先级决定「谁先补」，不决定「谁补多少」。
- **跨信源与跨版块去重**：同一篇论文同时上 HN 和 HF 时只留一条，并标注「另见 X」；一期之内互不重复。
- **200 字中文摘要**：由模型基于正文与社区热评撰写。抓不到正文时**如实标注「正文未能获取」并说明依据，绝不编造**；未写摘要的条目显式标「摘要待补」，不用自动文本填充。

## 各信源的实测可用性

| 信源 | 通道 | 实测结论 |
|---|---|---|
| Hacker News | Algolia API | ✅ 稳定。`numericFilters` 里的 `>` **必须** URL 编码为 `%3E` |
| Hugging Face | 页面内嵌 JSON + `api/daily_papers` | ✅ 稳定。`papers/trending` 是**历史热门榜**而非近期榜（实测 50 条中仅 8 条在 7 天内），必须用日报接口逐日补齐；**周末不发布日报**，空日属正常 |
| dev.to | 官方 API | ✅ 稳定。`?top=N` 语义恰好是「近 N 天热榜」 |
| Reddit | 仅 OAuth 或浏览器导出 | ⚠️ 免鉴权访问全面封锁：`www/old/api` 的 `.json` 返反爬 HTML，`.rss` 返 HTTP 200 但 **0 字节**，公共镜像 403 |

**HN Algolia 与 HF API 均允许跨域**（含 `Origin: null`，本地 `file://` 打开的页面也能抓）。这意味着页面本可自己联网更新 —— 之所以仍由脚本抓，是因为 200 字中文摘要需要模型，页面里没有。

## Reddit 的四种取数模式

按可用性自动降级，无需改代码：

1. **A · OAuth 凭证（首选）** —— `~/.claude/.reddit_env` 配置 `REDDIT_CLIENT_ID`、`REDDIT_CLIENT_SECRET`、`REDDIT_UA`（UA 必须含用户名，通用 UA 会被限流）。走 `client_credentials` 只读授权，拿不到私信、收藏、投票，也发不了帖。**凭证只经环境变量传递，不写入产物、不打印、不进日志。**
2. **B · 浏览器导出** —— 在已登录的浏览器打开 `https://www.reddit.com/r/LocalLLaMA/top.json?t=week&limit=100`，**右键 → 存储为**（或 DevTools Network 面板复制响应体）存成 `.json`。
3. **B-pdf · 打印版 PDF 还原** —— 若导出成了 PDF，`--reddit-json` 直接传 `.pdf` 即可，`pdf_to_reddit_json.py` 会还原成 listing。实测 100 条中 99 条核心字段完整。
4. **C · 跳过** —— 名额轮转转移，页面编者按显式说明「本期未采集」。**不假装采到了。**

### PDF 还原踩过的坑

- PDF 用**子集字体**存 CID 码（`<005E>` 才是 `{`），必须按对象图取**每个字体各自的** `/ToUnicode` CMap。合并成一张表会串码 —— 实测 `NVIDIA` 被解成 `NVI输IA`。
- 判断页眉页脚要**按行而非按字体**：标题里的 emoji 用的也是非正文字体，按字体过滤会把标题截断。
- 长值有**软换行**。JSON 美化输出每行必带缩进，故「不以空格开头的行」必是续行，据此重接。
- `bfrange` 的目标值可能是代理对，按码元递增，直接 `int(dst)+i` 会溢出码点上限。
- Chrome 打印长页面时**正文坐标跨页连续，页眉页脚却用页内坐标**，第 2 页起页脚的纵坐标会落进正文区间，被当成正文拼进去（实测 `"num_comments": 22` 变成 `h2/1322`）。改为按「过半页面都出现、且始终在固定纵坐标」识别页眉页脚字体，按字形剔除。
- 取消勾选「美观输出」打出的压缩版 JSON 可以整份 `json.loads`，最保真；美化版会被标题末尾的 emoji 截断字符串，只能走字段级容错提取。

## 目录结构

```
.
├── index.html               # 🐮 新闻板（GitHub Pages 主页）
├── digest.html              # 📰 日报
├── SKILL.md                 # skill 定义与三段式工作流，Claude 实际读的就是它
├── references/
│   └── ranking.md           # 排名口径的唯一事实来源，改口径先改这里
└── scripts/
    ├── fetch_rank.py        # 日报取数：抓取 → 去重 → 归一 → 打分 → 配额 → 正文提取
    ├── fetch_batches.py     # 新闻板取数：同源池内按分数切成等量批次
    ├── render_html.py       # 渲染日报
    ├── render_board.py      # 渲染新闻板（客户端渲染 + localStorage 收藏）
    └── pdf_to_reddit_json.py # 打印版 PDF → Reddit listing
```

两个渲染器都有 `--site-out PATH`，渲染时一并写入站点文件，**不靠事后手工复制**。

## 本地模型写摘要（可选）

不开 Claude 也能补摘要：`scripts/summarize_local.py` 调用本地 llama.cpp 的 `llama-server`（OpenAI 兼容接口），只补 `summaries.json` 里缺的条目，**已有摘要永不覆盖**。写作规范与 `SKILL.md` 第二段一致；输出不合格（非中文、过短过长、复述标题、空话）会带着原因重试一次，仍不合格就跳过，页面照常标「摘要待补」。本地模型写的条目记在 `.work/summaries_meta.json`，便于日后抽查或让 Claude 重写。

```bash
brew install llama.cpp
llama-server -hf inclusionAI/Ling-3.0-tiny-GGUF:Q6_K \
  -ngl 99 -c 16384 -np 1 -fa on --jinja --reasoning-budget 0 --port 8080   # 另开终端常驻

./run.sh summarize --limit 3   # 试跑三条
./run.sh all                   # 模型在线时 = 取数 + 写摘要 + 渲染；不在线则跳过写摘要
```

新闻板只有前 `--enrich-batches`（默认 2）批抓了正文，第 3 批起没有正文可依据，不会被补写。

## 前置条件

- Python 3，**仅用标准库，无需 `pip install`**（环境无 requests/bs4，PDF 解析也是手写的 zlib + 正则）。
- 收藏夹存在浏览器 localStorage 里，按页面地址隔离，重新发布同一地址不会清空；但换浏览器、清站点数据、无痕窗口会丢 —— 页面底部的备份面板是唯一兜底。

## 已知限制

- **新闻板的批次数由 HF 决定**，HN 每期还剩两百多条未进批次。
- **打印版 PDF 会丢失个别字符**（无字形的 emoji），且软换行边界偶有条目字段缺失 —— 脚本会显式列出并丢弃，不静默补默认值。
- **摘要按批补写**，第 3 批起默认没有中文摘要。
